# 사주플랜 앱 (WebView) 의 특수 동작

## 한 줄로 답하면
**사주플랜 앱은 RN WebView 셸 (앱 안에 사주플랜 웹 사이트). 일반 모바일 웹과 다른 특이점 몇 가지 있음 — 외부 URL 차단·캐시 갱신 지연 등.**

## 주요 특이점

### 웹앱 게이트 — 일반 브라우저 차단 (2026-06-12 신설)
- 사주플랜은 **앱 전용 서비스**. 일반 PC/모바일 브라우저로 `sajuplan.com` 에 직접 들어오면 **"앱에서 이용해주세요" 전체화면**이 뜨고 앱 설치를 유도한다.
- **PC 브라우저**: 앱 로고 + 마스코트 안내 + **QR 코드 2개**(Google Play / App Store) → 폰 카메라로 찍어 설치.
- **모바일 브라우저**: 스토어로 바로 가는 탭 버튼(받기).
- **앱(WebView) 안에서는 게이트 안 뜸** → 정상 이용.
- 스토어 링크는 강제업데이트와 **같은 출처**(환경설정 앱 버전값)에서 가져온다 (한 곳만 고치면 둘 다 반영).
- **운영자가 브라우저로 점검**해야 할 땐: 주소창 콘솔에서 `localStorage.__allow_web__='1'` 넣고 새로고침하면 게이트가 풀린다.

### 외부 URL 차단
- 앱 WebView 안에서 외부 사이트 클릭하면 새 탭 안 열림
- "openExternalUrl" 같은 별도 처리 필요 (사주플랜 시스템이 알아서)

### 캐시 갱신 지연
- 앱이 옛 화면 캐시하고 있을 수 있음
- 새 정책 배포 후 일부 사용자에게 옛 화면 보이는 경우 가능
- 강제 새로고침 또는 시간 지나면 갱신

### 알림 → 앱 자동 이동 (푸시/FCM 이동 방식 — 안드로이드·iOS 모두 정상)
- 카카오 알림톡 클릭 시 앱 이동 = **푸시/FCM 이동 방식**. 안드로이드·iOS 둘 다 동일 기능으로 등록·구현됨 (정상). 앱이 꺼져 있어도 켜지고 **정확한 페이지로 이동**됨.
- BizM 설정·백엔드·서버·사주플랜 코드 = 변경 0 (정상). 안드로이드가 정상이므로 BizM/서버 문제 아님. **BizM·서버 변경 불필요.**
- 일부 아이폰 에러 제보는 iOS 기능 자체는 등록돼 있으므로 **그 단말의 앱 미설치/구버전 등 환경 가능성** (단정 금지).

## 이런 상황을 보셨나요?

### "회원이 옛 화면 보고 있대요"

→ 캐시 가능성 1순위. 강제 새로고침 안내. 그래도 안 되면 시스템 사고.

### "외부 링크 클릭이 안 돼요"

→ WebView 한계. 사주플랜 화면에서 외부 사이트는 별도 처리 필요. 운영자가 등록한 외부 링크 (배너, 공지 등) 가 안 되면 시스템 점검.

### "알림톡 클릭하니 카톡 브라우저에서 사주플랜 사이트가 열려요"

→ 카카오 알림톡 클릭 시 앱 이동은 푸시/FCM 이동 방식이며 안드로이드·iOS 모두 정상 등록. 앱이 꺼져 있어도 켜지고 정확한 페이지로 이동됨. BizM·서버 변경 불필요.

## 이건 정상인가요? 에러인가요?

| 상황 | 답변 |
|---|---|
| 앱 안에서 사주플랜 동작 | ✅ 정상 |
| PC/모바일 브라우저로 접속 → "앱에서 이용해주세요" 화면 | ✅ 정상 (앱 전용 게이트) |
| 게이트에 QR/스토어 버튼 노출 | ✅ 정상 |
| 운영자가 브라우저 점검 시 게이트 풀고 싶음 | `localStorage.__allow_web__='1'` 후 새로고침 |
| 외부 사이트 클릭 → 시스템 브라우저 열림 | ✅ 정상 (sajuplan 자동 처리) |
| 옛 캐시로 옛 화면 노출 | ⚠️ 일시적 |
| 알림톡 클릭 → 앱 켜지고 정확한 페이지로 이동 | ✅ 정상 (푸시/FCM 이동 방식, 안드로이드·iOS 모두 정상) |
| 일부 아이폰에서만 이동 에러 제보 | ⚠️ 그 단말의 앱 미설치/구버전 등 환경 가능성 (단정 금지). 기능은 양 OS 정상 등록, BizM·서버 변경 불필요 |
| 회원이 앱 못 열어요 | ❌ APK 다운로드 / 설치 안내 |
