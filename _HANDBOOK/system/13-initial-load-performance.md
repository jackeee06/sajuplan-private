# 초기 로딩 속도 최적화 (2026-06-25)

## 한 줄로 답하면
**"앱 첫 화면이 2~3일째 느려졌다"의 원인은 서버가 아니라 홈 첫 화면에 상담사 카드(=프로필 사진)를 한꺼번에 너무 많이 띄운 것. 사진을 화면에 보이는 만큼만 받게(lazy) + 첫 화면 카드 수를 줄여서 해결했다. 서버·DB는 멀쩡하다(응답 4~5밀리초).**

---

## 무슨 문제였나 (쉬운 말로)

사장님이 "요 2~3일 사이 앱 첫 화면이 느려졌다"고 하셨다. 확인해보니:

- **서버·DB는 전혀 안 느림** — 서버 안에서 직접 재보면 모든 응답이 **4~5밀리초**(눈 깜짝할 새), 서버 부하도 0. (해외에서 측정하면 1~2초로 보이는데, 그건 한국까지의 인터넷 거리·암호화 연결 시간일 뿐 서버 탓이 아니다.)
- **진짜 원인은 홈 첫 화면의 상담사 카드 수.** 2026-06-23 에 "첫 화면에 상담사를 거의 다 보이게" 하려고 **20명 → 30명**으로 늘렸는데, 카드마다 프로필 사진이 있어서 **첫 화면에서 사진 30장을 한꺼번에 다운로드** → 느려짐. 사장님 직감("상담사 많이 보여줘서?")이 정확했다.

---

## 어떻게 해결했나 (적용 완료·배포됨)

1. **카드 사진 "보이는 만큼만" 받기 (lazy 로딩)**
   - 상담사 카드 사진에 "화면에 보일 때 받기" 설정을 켰다. 스크롤해서 내려야 보이는 카드 사진은 미리 안 받는다.
2. **첫 화면 상담사 30명 → 12명**
   - 나머지는 "더보기"로 펼친다. 첫 화면이 가벼워졌다.
3. **올리는 사진 크기 상한(가로 1280)**
   - 상담사·배너·이벤트·팝업·공지 사진을 올릴 때 너무 큰 원본은 자동으로 적당한 크기로 줄여 저장(앞으로 올리는 사진부터 적용).

→ 결과: 홈 첫 화면 사진이 12장 + 화면 밖은 스크롤 시 로드. 실제 운영 사이트에서 확인 완료(E2E 16건 통과).

---

## ✅ "코드 분할"도 완료 (2026-06-25 배포)

가장 효과 큰 추가 최적화 — **앱 코드를 화면별로 쪼개서 첫 로딩 때 필요한 것만 받게** 하는 작업(코드 분할)을 끝냈다. 첫 로딩 JS 용량을 **1.5MB → 약 331KB(약 79% 가벼움)** 으로 줄였다.

- ⚠️ **"화면이 79% 빨라진다"는 뜻이 아니다.** "첫 로딩에 받는 코드가 79% 가벼워진다"는 뜻이고, 체감은 첫 로딩이 살짝 산뜻해지는 **보너스** 수준(대략 0.3~1초).
- **숨은 큰 장점**: 이제 기능을 아무리 추가해도 첫 로딩 코드가 안 부풀어 오른다(새 화면은 자동으로 따로 분리됨).
- **왜 한 번 멈췄었나 → 진짜 원인**: 예전에 시도했을 때 화면 이동 시 앱이 멈췄는데, 알고 보니 라우팅 뼈대 문제가 **아니라**, 캐시 새로고침용으로 파일 주소 뒤에 붙이던 `?v` 표시가 화면별로 쪼갠 코드와 충돌해 **같은 코드 파일을 두 번 받아버리는** 것이 원인이었다. 그 `?v` 를 코드 파일(.js)에는 안 붙이도록 한 줄 고쳐서 해결했다(코드 파일은 이미 이름 자체가 매번 바뀌어 새로고침이 보장됨).
- **검증**: 운영 사이트에서 90개 화면 + 화면 이동을 자동으로 전부 눌러봐 멈춤 0건 확인, 기존 자동테스트도 전부 통과. 사용자 노출 전 로컬에서 먼저 똑같이 검증하는 안전장치(자동 클릭 도구)를 만들어 통과시킨 뒤 배포했다.

## 이건 정상인가요?

| 상황 | 판단 |
|---|---|
| 해외/먼 곳에서 열면 느리고 한국에선 빠름 | ✅ 정상 — 거리·연결 시간 차이(서버 탓 아님) |
| 홈 첫 화면에 상담사 12명, 더보기로 펼침 | ✅ 정상 (2026-06-25 변경) |
| 스크롤 내려야 그때 사진이 뜸 | ✅ 정상 (lazy 로딩) |
| 첫 화면이 갑자기 또 느려짐 | ⚠️ 첫 화면 상담사 수를 다시 늘렸는지 확인 (카드=사진 수가 핵심) |
| 새 배포 직후 한 번 느리고 그 다음 빠름 | ✅ 정상 — 새 코드 1회 받는 것(캐시) |

## 점검은 어떻게 했나
- 서버 안에서 직접 응답시간 측정(4~5ms) + 부하 0 확인 → 서버 무관 입증.
- 실제 운영 사이트에서 홈 12장·lazy 동작·화면 이동 무사 확인, E2E `02·07·28·114` 16/16 통과.
