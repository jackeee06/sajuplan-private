# 콘텐츠 XSS 정화 — 악성 HTML 차단 (2026-06-12)

## 한 줄로 답하면
**공지·이벤트·팝업·상담사 소개글·채팅처럼 "글에 서식(HTML)을 넣을 수 있는" 모든 화면에서, 누가 악성 코드를 심어도 글자만 안전하게 보이고 코드는 실행되지 않도록 DOMPurify(검증된 정화 도구)로 막아뒀다.**

---

## 무슨 문제였나 (쉬운 말로)

사주플랜 곳곳에는 운영자나 사용자가 **글에 서식을 넣는** 자리가 있다 — 공지 본문, 이벤트 안내, 팝업, 상담사 소개글, 약관, 그리고 **채팅 메시지**.
이런 글은 화면에 "꾸며진 모양 그대로(HTML)" 그려진다.

문제는, 글 안에 `<img onerror="나쁜코드">` 나 `<script>` 같은 **악성 코드**를 몰래 끼워 넣으면, **그 글을 보는 사람의 화면에서 그 코드가 실제로 실행**될 수 있다는 점이다. 이런 공격을 **XSS(저장형 크로스사이트 스크립팅)** 라고 한다.
- 예: 어떤 회원이 상담사에게 채팅으로 악성 코드가 든 메시지를 보내면 → 상담사가 그 채팅을 열어보는 순간 상담사 브라우저에서 코드가 실행 → 쿠키·세션 탈취 등으로 이어질 수 있다.

이전엔 "위험해 보이는 단어를 찾아서 지우는" 방식(블랙리스트)으로 막고 있었는데, 이 방식은 **빠뜨리는 구멍이 생기기 쉽다** (새로운 우회 기법이 계속 나옴).

---

## 어떻게 막았나

### 1. 정화 방식을 "화이트리스트"로 교체 (DOMPurify)
- "위험한 걸 지운다(블랙리스트)" → **"안전한 것만 남긴다(화이트리스트)"** 로 바꿨다.
- **DOMPurify** — 전 세계가 쓰는 검증된 XSS 정화 라이브러리. 안전한 서식(굵게·줄바꿈·링크·이미지 등)만 통과시키고, `onerror`·`<script>`·`javascript:` 같은 실행 코드는 전부 제거한다.
- 글을 화면에 그리기 **직전에** 무조건 한 번 정화한다 (`sanitizeIntroHtml`).

### 2. 적용 범위 (서식 글이 보이는 모든 화면)
- 공지 상세 / 이벤트 상세 / 알림 상세
- 팝업 본문
- 상담사 소개글 / 상담사 공지
- 약관·처리방침
- 상담사 신청서 (회원·관리자 양쪽)
- **채팅 메시지** (회원↔상담사) — 가장 위험했던 자리

### 3. 채팅 악성 HTML 차단 (실제 손가락 검증 완료)
- 채팅에서 "이 메시지는 HTML로 그려라" 표시가 붙은 글도 이제 그리기 직전 정화된다.
- 실제로 회원 계정으로 `<img onerror=...>` 악성 메시지를 진짜 전송해보고, 상담사가 그 채팅을 열었을 때:
  - 메시지 **글자는 정상 표시**
  - 악성 코드는 **실행되지 않음** (정화로 제거됨)
  - 확인 완료.

---

## 이건 정상인가요? 에러인가요?

| 상황 | 판단 |
|---|---|
| 공지·이벤트·팝업에 굵게·링크·이미지 서식 → 그대로 보임 | ✅ 정상 (안전한 서식은 통과) |
| 글/채팅에 악성 코드 → 글자만 보이고 코드 실행 안 됨 | ✅ 정상 (정화됨) |
| 채팅 악성 메시지 → 상담사 화면에서 코드 실행됨 | ❌ 비정상 (발생 시 즉시 보고 — 정화 누락) |
| 정상 서식인데 일부가 사라져 보임 | ⚠️ 정화가 위험으로 오판 가능. 보고 시 화이트리스트 조정 |

---

## 점검은 어떻게 했나

실제로 악성 코드를 **일부러 심어 보내고**, 보는 쪽 화면에서 **코드가 실행되는지** 자동으로 확인하는 방식.
- 채팅 XSS: `e2e/tests/77-chat-xss.spec.ts` — 회원이 `<img onerror>` 전송 → 상담사 화면에서 `onerror` 미실행 + 텍스트 정상 노출 + DOM에 onerror 잔존 0건 확인. **통과.**
- 테스트로 만든 채팅방·메시지는 검증 후 **운영 DB에서 즉시 삭제** (운영 데이터 오염 0).
