# 채팅 도중 화면을 벗어나면 어떻게 되나요?

## 한 줄로 답하면
**잠깐 백그라운드(알림 확인·앱 전환·화면 잠금)로 나가도 채팅은 죽지 않고 그대로 살아있습니다. 단, 상담이 시작된 뒤(상담사 입장 후)에는 누가 자리를 비우든 m2net이 실시간으로 과금하므로 과금은 계속됩니다.** (2026-06-17 개편)

## 🔴 2026-06-17에 무엇이 바뀌었나요?

**예전 사고:** 회원·상담사가 채팅 중 폰을 잠깐 백그라운드로 보내면(알림 확인 등) `pagehide` 이벤트가 떠서 **채팅이 즉시 종료**돼 버렸습니다. iOS 앱이 백그라운드 전환 때마다 이 이벤트를 쏘기 때문에, **상담 중에 채팅이 자꾸 끊기는** 사고가 있었습니다. (실제: 상담사가 "성별은요?" 묻고 폰 잠깐 본 사이 채팅 종료, 회원 10분 남기고 끊김)

**지금:** 백그라운드/탭닫기/포커스 이탈을 **"즉시 종료" → "잠시 이탈(복구 가능)"** 으로 바꿨습니다.
- 돌아오면(앱 복귀) 채팅이 그대로 이어집니다 — 끊기지 않습니다.
- 진짜로 떠난 방(양쪽 다 나가고 3분 이상 아무 대화 없음)만 자동 정산·종료됩니다.
- 정식 종료는 **"상담종료" 버튼**을 누를 때만.

## ⭐ 과금 원칙 (제일 중요 — 헷갈리지 마세요)

| 시점 | 과금 |
|---|---|
| **상담사 입장 전 (STAY)** | **차감 0** — 상담이 시작 안 됐으니 m2net도 과금 안 함 (F 정책, 회원 보호) |
| **상담 중 (CNCH)** | **계속 과금** — 회원이든 상담사든 잠깐 자리를 비워도 m2net이 세션 살아있는 한 실시간으로 계속 빼갑니다. 우리도 똑같이 과금합니다. |

> **왜 상담 중엔 안 멈추나요?** m2net은 누가 딴짓하든 상관없이 실시간으로 회원에게서 돈을 빼갑니다. 우리가 "이탈했으니 과금 정지"를 하면 → m2net은 돈을 가져갔는데 사주플랜만 안 받아 → **사주플랜만 적자**. 경쟁사도 상담사·고객이 딴짓해도 과금을 끊지 않습니다. 이탈은 **당사자 책임**(고객 사정은 본인 잘못, 상담사 딴짓은 후기로 심판).

## 이런 상황을 보셨나요?

### 회원이 "채팅 중에 잠깐 다른 앱 봤다가 돌아왔어요" 라고 함
→ **채팅 그대로 살아있습니다.** 더 이상 백그라운드로 끊기지 않습니다. 단, 그 잠깐 동안에도 상담은 진행 중으로 보고 과금은 계속됩니다(상담사가 메시지 남겼을 수 있고, m2net도 과금 중).

### "상담사가 답하다 말고 갑자기 사라졌어요 / 채팅이 끊겼어요"
→ 2026-06-17 개편 후엔 **상담사가 잠깐 백그라운드 가도 안 끊깁니다.** 그래도 끊겼다면: ① 상담사가 직접 "상담종료" 버튼을 눌렀거나 ② 둘 다 3분 이상 아무 대화 없이 방치돼 자동 정산됐거나 ③ 시간(코인) 소진. 채팅내역에서 마지막 메시지·종료 시각 확인.

### "채팅 신청만 했는데 상담사가 안 와서 닫았어요"
→ **차감 0원입니다.** 상담사 입장 전(STAY)엔 어떤 경우에도 코인이 안 빠집니다 (F 정책). 환불 불필요.

### **상담관리 → 채팅내역 리스트** 에서 자동 종료가 보임
→ 정상. ① 상담사 미입장 3분 → 자동 취소(알림톡 발송) ② 상담 중인데 양쪽 다 나가고 3분 무활동 → 자동 정산 종료.

## 종료되는 경우 (정리)

| 경우 | 처리 |
|---|---|
| "상담종료" 버튼 클릭 | 즉시 정식 종료 + 정산 (확인 모달 후) |
| 백그라운드/탭닫기/새로고침 | **종료 안 됨** — 잠시 이탈로 처리, 복귀하면 그대로 |
| 상담사 미입장 STAY 3분 | 자동 취소 (차감 0, 양쪽 알림톡) |
| 상담 중인데 양쪽 다 나가고 3분 무활동 | 자동 정산 종료 (방치 정리) |
| 코인(시간) 소진 | 자동 종료 + 정산 |
| 5초/30초 내 종료 | 단기 환불 정책 적용 ([환불](payment/04-refund) 참조) |

## 방치 채팅 자동 정산 (청소부 cron) — `settleAbandonedChats`

### 왜 필요한가
백그라운드로 채팅을 **안 죽이게** 바꾸니(2026-06-17) 부작용이 하나 생깁니다: 누가 **진짜로 떠나버리면**(앱 완전 종료, 둘 다 사라짐) 그 채팅방이 "살아있는 채로 영원히" 남게 됩니다. 그래서 **진짜 죽은 방만 골라 마무리 정산하는 청소부**가 필요합니다. → `settleAbandonedChats` cron, **매분 실행**.

### 언제 작동하나 — 3가지 조건을 **전부** 만족할 때만
```
① status = 'CNCH'              (진행 중인 채팅만)
② 한쪽이라도 "이탈" 표시됨        (member 또는 counselor 가 자리를 비움 = try_out)
③ 마지막 메시지가 3분 넘게 없음    (완전 정적)
```
세 개가 **동시에** 맞아야 합니다. 하나라도 아니면 안 건드립니다.

### 왜 안전한가 (활성 채팅 오종료 0)
| 상황 | 걸리나? | 이유 |
|---|---|---|
| 둘 다 대화 중 (정상) | ❌ 안 걸림 | 아무도 이탈 표시 없음 (②번 불충족) |
| 느린 대화 (3분간 고민) | ❌ 안 걸림 | 둘 다 자리 있음 → ② 불충족 |
| 잠깐 백그라운드 갔다 복귀 | ❌ 안 걸림 | 복귀하면 rejoin이 이탈 표시 해제 → ② 풀림 |
| **상담사·회원 둘 다 떠나고 3분 무음** | ✅ 걸림 | ①②③ 모두 충족 = 진짜 죽은 방 |

즉 **"누군가 실제로 떠났고 + 3분간 아무 말 없음"** 일 때만 = 명백히 끝난 방.

### 걸리면 뭘 하나
1. 방을 **DISCONNECT(종료)** 표시
2. **`settleChatRoomLocal`** 호출 — 정상 종료와 **똑같은 정산 함수**. m2net 실제 과금과 맞춰 정산하고, 미사용 선결제는 환불, 상담 기록 남김.

→ **돈은 정확히 정산됩니다** (m2net 기준이라 사주플랜 손실 없음). 과금을 *멈추는* 게 아니라, **이미 죽은 방을 마무리**하는 것입니다.

### 시나리오
- **앱을 완전히 닫은 회원**: 닫는 순간 soft 이탈 표시 → 이후 메시지 없음 → 3분 뒤 cron이 정산(미사용분 환불). *예전엔 즉시 정산됐는데 지금은 3분 뒤 — 그 대신 잠깐 백그라운드론 안 끊김.*
- **상담사가 가버리고 회원도 포기**: 둘 다 이탈 + 무음 → cron 정산, 회원 환불.
- **정상/느린/잠깐 채팅**: 전부 그냥 진행. cron 손 안 댐.

### 현재 상태 + 조절
- 매칭 시 `chat/auto-cancel` cron 응답에 `abandoned:{settled:N}` 로 집계.
- **"3분"은 조절 가능**: 너무 짧으면 조용한 활성 채팅 위험, 너무 길면 죽은 방이 오래 남음. 현재 3분 = 안전하게 잡음(운영 보며 늘릴 수 있음).

## 이건 정상인가요? 에러인가요?

| 클레임 | 답변 |
|---|---|
| "잠깐 카톡 봤다가 돌아왔는데 채팅 끊겼어요" | ❌ **사고** (2026-06-17 이후엔 안 끊겨야 정상). 끊겼다면 즉시 점검 — 배포 캐시(WebView 옛 코드)도 의심. |
| "상담사 안 들어왔는데 코인 빠졌어요" | ❌ **사고**. F 정책 위반. 보고+점검. |
| "상담 중에 잠깐 자리 비운 동안 과금됐어요" | ✅ **정상**. 상담 중(CNCH)은 m2net 실시간 과금이라 계속 과금. |
| "상담사가 5분 만에 끊었는데 15분 결제했어요" | ⚠️ 상담사 조기 종료. 미사용분 환불 대상일 수 있음 — m2net 실과금과 대조 후 환불 검토. |

## 운영자가 확인하는 위치

| 확인 항목 | 메뉴 위치 |
|---|---|
| 채팅 종료·대화 내역 보기 | 사이드바 → 상담관리 → 채팅내역 리스트 (행 클릭 → 대화 전체) |
| 환불 처리 (수동) | 사이드바 → 매출현황 → 환불 이력 |
| 과금 정책 | [채팅 과금 정책](chat/07-billing-policy) |

## 정책을 바꾸고 싶다면
- **방치 정산 임계(3분)** 조정 가능. 너무 짧으면 조용한 활성 채팅을 끊을 위험, 너무 길면 죽은 방이 오래 남음.
- **F 정책(상담사 입장 전 차감 0)** · **CNCH 계속 과금** 은 핵심 정책 — 변경은 사장님 명시 지시 후에만.
